**教訓(2026-07-25)**:WorkflowUI 的 `/api/health` 對 `192.168.1.161:8188` 打 HTTP 失敗後,我直接跟
使用者說「這個環境連不到 .161」——這個結論下得太快、太籠統。使用者追問「你不能用 ssh 測?」,一測發現
SSH 完全通、ComfyUI 也真的在跑,我的結論是錯的,講得語焉不詳還誤導了對話方向。

**Why**:HTTP 連線失敗只證明「這一種連法失敗」,不能跳到「這台機器/這個網段連不到」的籠統結論——
沙盒/防火牆常常是針對特定協定或 port 放行,不是全有全無。真正該做的是**換一種連法實測**(這裡是
SSH),而不是憑一次失敗就下定論說死。

**How to apply**:
- 對外部主機/服務的可達性下結論前,如果有不只一種連線方式(HTTP / SSH / ping / 其他 port),至少
  多測一種再下結論,不要只憑第一次失敗就概括。
- 跟使用者報告時,講清楚「我測了 X 方式失敗」而不是籠統講「連不到」——後者聽起來像已經窮盡查證,
  容易誤導對方省略掉可能可行的替代路徑。
- 使用者反過來提示「你不能用 XXX 測?」時,這通常代表我漏了一條路,應該先去實測再回答,不要用猜的
  或用理論推斷回覆。
